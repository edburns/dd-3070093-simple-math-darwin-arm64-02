## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Manifest consistency:** The run manifest exactly matches the supplied campaign identity, repository, base, issue list, control lesson mode, and exit code.
- **Lifecycle gating:** Stage 30 waited for CCA work-cycle completion and verified an effective diff rather than assuming PR creation meant implementation completion.
- **Evidence-based readiness:** Both tasks passed repository-owned Pester execution, two pinned workflow checks, file-scope checks, review-state checks, and HEAD-stability checks.
- **Review convergence:** One finding was fixed in one remediation cycle; the dependent task then passed CCRA review without findings.
- **Regression preservation:** The second task retained default Fibonacci behavior while adding factorial dispatch, and expanded acceptance coverage from 9 to 23 passing tests.
- **Control isolation:** `lessonPropagation: off` was preserved, and `campaign-lessons.md` remained empty, avoiding treatment leakage into this control run.
- **Cleanup:** Temporary validation/review worktrees and branches were removed after use.

### 8.2 What Could Be Improved

- **Token observability:** OTEL captured token attributes but redacted their values, preventing token-based comparison with other campaign runs.
- **Review metric normalization:** Current CCRA output uses `Findings` rather than the older `Comments generated` wording. Post-mortem tooling should recognize both representations.
- **Orchestration accounting:** Session exports explain 50m 30s of the 57m 56s campaign. Explicit stage-transition timestamps in the run manifest would make the remaining 7m 26s directly attributable.
- **Duplicate status closure:** Stage 40 uses issue closure commands even when merge automation may already close an issue. The observed `|| true` is harmless here but obscures whether closure was automatic or explicit.

### 8.3 Recommendations

1. **Export unredacted aggregate token counters when policy permits.** Numeric session totals are sufficient; prompt or response content is unnecessary.
2. **Emit a machine-readable per-stage summary.** Include issue, PR, start/end, phase duration, review IDs, findings count, remediation commits, tests, checks, merge commit, and outcome. This would eliminate transcript parsing.
3. **Normalize CCRA convergence fields.** Record `reviewRounds`, `lineFindings`, `resolvedFindings`, and `finalUnresolvedFindings` independently of UI wording.
4. **Preserve original-value validation for PowerShell numeric inputs.** The [#4](https://github.com/edburns/dd-3070093-simple-math-darwin-arm64-02/pull/4) finding demonstrates that typed parameter binding can coerce before validation; future issues should test fractional strings at both function and process boundaries.
5. **Keep dependency-ordered serialization for this campaign shape.** [#3](https://github.com/edburns/dd-3070093-simple-math-darwin-arm64-02/issues/3) built directly on [#2](https://github.com/edburns/dd-3070093-simple-math-darwin-arm64-02/issues/2), and the short second-task cycle indicates that merging the foundation first reduced integration risk.
6. **Retain explicit review acknowledgement and stable-HEAD gates.** These guardrails produced observable review completion and prevented merge against an unreviewed commit.
